# Writing agent instructions and workflows

Apply when creating or changing rules, skills, subagents, or agent-tool workflows.

  * Before adding an instruction, identify the concrete mistake it prevents or the necessary context it supplies. Keep one authoritative source: if existing guidance covers that need, clarify it only when necessary rather than adding a duplicate.
  * Keep always-loaded rules for durable constraints and expectations, plus necessary context the agent cannot reliably infer. Put task-specific procedures, scripts, and detailed examples in skills or references loaded when needed. A specialised topic alone does not make an instruction a skill. Use the narrowest applicable scope. Keep temporary task state out of permanent policy.
  * Write direct instructions in plain language. Use consistent terms and describe concrete actions and expected results rather than vague goals. Make clear who should act when that could be misunderstood. If "it," "this," or "they" could refer to different things, name the intended item. Add a short example only when needed to prevent ambiguity.
  * Put conditions before the actions they qualify and keep exceptions nearby, so loading a rule does not itself start unrelated work. Where a prohibition leaves the next action unclear, state a safe alternative without weakening the restriction. Preserve technical precision and safety limits.
  * For each reference, give a verified path or authoritative URL and state when to read it. Keep essential safety and approval boundaries in the applicable entry point, not solely optional links. Do not require unrelated references together.
  * Keep skill and subagent descriptions short: purpose and when to use them. Put required inputs, outputs, and procedures in the body. When writing a skill, subagent, or workflow, state how to tell when the work is complete. Check the target agent's format and loading behaviour; do not assume inherited context or capabilities. Choose whether a skill or workflow may start automatically or needs an explicit user request. Set supported activation controls to match.
  * For workflows that repeat or delegate work, define stop conditions and task-appropriate limits on total iterations or agent runs, not just how many run at once. Enforce limits with available workflow controls; report unfinished work when a limit is reached.
  * For changes to activation, permissions, or workflows, verify representative affected cases. Where relevant, also check cases where the rule or workflow should not apply. Before claiming improved agent behaviour, compare the previous and revised instructions on representative tasks under comparable conditions. Limit claims to what was tested. Review wording-only changes for clarity, consistency, and unchanged meaning.
